# Vitrum

Android-клиент VPN на ядре [Xray](https://github.com/XTLS/Xray-core). Показывает, что в защите работает, а что нет, и отдельно помечает то, что не удалось проверить.

*An Android VPN client built on Xray, with a privacy self-check, connection log, kill switch, split tunneling and a game mode. Russian and English interface.*

Версия 1.0.0, только arm64, Android 8.0 и новее. Часть функций проверена на телефоне, остальное покрыто модульными тестами и проверкой конфигов настоящим Xray (подробности в [`docs/HANDOFF.md`](docs/HANDOFF.md), история версий в [`CHANGELOG.md`](CHANGELOG.md)). Если что-то не работает, откройте Issue с описанием.

## Возможности
- Протоколы: vless, vmess, trojan, shadowsocks, hysteria2 (Reality, TLS, xhttp, gRPC, WebSocket и другие транспорты).
- Подписки по https: метаданные панели (трафик, срок, объявление, интервал обновления, переезд на новый адрес и запасной адрес с подтверждением) и JSON-режим с авто-серверами.
- Защита: kill switch, переподключение при смене сети, автопереключение серверов, сценарии по типу сети (Wi-Fi, мобильная, роуминг, открытая Wi-Fi), расписание VPN, журнал соединений.
- Щит приватности: оценка защиты, где критичная проблема не даёт высокой оценки, а непроверенное очков не приносит.
- Маршрутизация: профили, раздельное туннелирование по приложениям, режим «Все, кроме РФ», белый список, собственные правила для доменов, адресов и портов, DNS и DoH.
- Игры: «Игры мимо VPN» (Steam, Riot, Battle.net, Epic, EA, Ubisoft, FACEIT), игровой режим с живым пингом, джиттером и потерями.
- Замер серверов (HEAD, TCP, ICMP, скорость), рейтинг стабильности, трафик по приложениям, плитка быстрых настроек, QR-коды.
- Необязательные root-функции (выключены по умолчанию, без включения `su` не вызывается): кто слушает порты на 127.0.0.1, сравнение признаков VPN с системой, настройка работы в фоне.
- Резервная копия настроек и серверов в файле `.vitrumbak` (шифруется паролем), блокировка приложения и виджет.
- Без аналитики и рекламы.

## Установка
1. Скачайте APK на странице [Releases](https://github.com/lolokeksu09/Vitrum/releases) (список изменений: [`CHANGELOG.md`](CHANGELOG.md)). Релизы собирает GitHub Actions. Основной файл — `Vitrum-X.Y.Z.apk` (конфигурация release, подпись ключом автора, обновляется поверх установленных сборок автора); `Vitrum-X.Y.Z-debug-fallback.apk` — запасная отладочная, подписана одноразовым ключом сборки. Если в описании релиза указано, что подпись одноразовая (`…-release-debugsigned.apk`), такой файл поверх сборки с ключом автора не встанет (и наоборот): сначала удалите установленную.
2. Подпись выпуска автора (SHA-256 сертификата): `8cb8b675f97239948f0b93ac4208464e856397d6141268798129c00337205c61`. Ключ выпуска сменён 2026-10-08: сборка 0.24.1 была подписана прежним ключом и поверх этих версий не обновится, один раз нужно удалить её (перед этим сделайте резервную копию в «Настройки → Защита»). Проверить: `apksigner verify --print-certs файл.apk` или в приложении «Настройки → О приложении → Подпись приложения».
3. При первом подключении Android спросит разрешение VPN. На прошивках с агрессивной экономией батареи (например, ColorOS) выберите для приложения «Без ограничений».

## Сборка из исходников
Нужны Linux или WSL, JDK 21 и Android SDK 35.
```
tools/SETUP_ENV.sh               # JDK и SDK на чистой машине
tools/FETCH_BINARIES.sh --linux  # Xray 26.3.27 с проверкой контрольной суммы
tools/build.sh tests             # модульные тесты
tools/build.sh debug             # отладочный APK
```
Релизная сборка подписывается вашим ключом: положите `keystore/vitrum-release.jks` и задайте пароль в `VITRUM_KS_PASS`. APK с другой подписью не обновит установленный выпуск автора.

На GitHub Actions сборка (`.github/workflows/build.yml`) запускается только по тегу `v*` или вручную: тесты, отладочный и release-APK и пре-релиз с ними. Состояние проекта и устройство кода описаны в [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Приватность
Приложение обращается только к этим адресам:
- адрес вашей подписки и серверы из неё;
- `api.ipify.org`, `icanhazip.com`, `ifconfig.me`: узнать ваш IP, когда вы сами запускаете проверку Щита;
- `cp.cloudflare.com`: замер задержки (адрес можно изменить);
- `raw.githubusercontent.com`: обновление белого списка, если он включён;
- `stat.ripe.net`: подсети игровых серверов, если включены эти наборы;
- `github.com` (runetfreedom): база IP для России, если вы её включили (около 18 МБ);
- адрес `update.json`, если вы его указали.

HWID и данные устройства панели не отправляются. Ссылки серверов хранятся зашифрованными (ключ в Android Keystore). Открытых портов на `127.0.0.1` нет: служебные входы Xray работают на unix-сокетах.

## Чего приложение не делает
Vitrum не скрывает VPN от других приложений (банков, госсервисов): нет подмены признаков VPN, хуков и скрытия root. Для таких приложений есть штатный путь: «Маршруты → Программы → Кроме выбранных» или кнопка «Банки и госуслуги мимо VPN». Трафик исключённого приложения идёт мимо VPN, но признаки VPN на телефоне (интерфейс `tun`, сеть VPN в списке сетей) могут остаться видны. Что видно приложению вне туннеля, показывает «Щит → Что видят другие приложения» (без root). Скрывать такие признаки умеют внешние модули для телефонов с root (например, [vpnhide](https://github.com/okhsunrog/vpnhide), MIT); Vitrum их не ставит и не настраивает, совместимость не проверялась.

Kill switch держит туннель открытым и не читает его, пока Xray остановлен. Исключённые из VPN приложения в туннель не попадают, поэтому kill switch их не отключает (вывод по коду, на устройстве не проверено). Как с ними работает системная блокировка «Блокировать соединения без VPN», неизвестно: проверьте на телефоне.

## Как ведётся разработка
Проект разрабатывается с помощью ИИ-ассистента ([Claude Code](https://claude.com/claude-code)): большая часть кода и документации написана ассистентом, автор ставит задачи и принимает решения, работу приложения на телефоне проверяет автор. Правила для ИИ-агентов, работающих с репозиторием, лежат в [`AGENTS.md`](AGENTS.md) и [`CLAUDE.md`](CLAUDE.md), состояние проекта в [`docs/HANDOFF.md`](docs/HANDOFF.md). Что проверено запуском, что только по коду, а что не проверено на устройстве, указано в [`docs/HANDOFF.md`](docs/HANDOFF.md) и в заметках выпусков (`docs/releases/`).
