# Правила для ИИ-агентов (Claude Code, Codex и другие)

Состояние проекта и что осталось: `docs/HANDOFF.md`, история версий: `CHANGELOG.md`. Читай HANDOFF перед работой.

## Как работать с автором
1. **Язык:** русский, коротко. Сначала результат, потом детали. Без вступлений и пересказа вопроса.
2. **Шаги:** идём по согласованному плану. Закончил шаг, остановился, отчитался, ждёшь «дальше». Следующий шаг (даже «только чтение») сам не начинай.
3. **Честность:** помечай, на чём основано утверждение: факт из кода или контекста, проверено запуском (тест, `xray run -test`, живой Xray), проверено поиском, предположение. Не знаешь: пиши «не знаю», не достраивай. Источники оценивай (реклама, заинтересованность).
4. **Устройство:** приложение на телефоне проверяется автором. Пока он не подтвердил, пиши «не проверено на устройстве».
5. **Минимальные правки:** меняй только то, о чём просили. О ломающих изменениях (формат хранилища, версии инструментов, права, манифест, схема сети) предупреждай до, а не после.
6. **Имена:** названия проектов, файлов, переменных и терминов автора сохраняй без замен.
7. **Выбор:** если автор думает вслух или выбирает, разбирай варианты с критериями (польза, усилие, риск), не выдавай один ответ. Не больше одного вопроса за раз.
8. **Свежая среда:** скрипты и команды рассчитывай на чистую машину (`apt-get update` перед установкой, проверка, что утилита или папка есть).

## Секреты (жёстко)
- Никогда не печатай и не коммить: ключ подписи `keystore/vitrum-release.jks`, пароль к нему, токен или адрес подписки, настоящие ссылки серверов, ответ `/json` панели.
- Пароль и токен читай из файла сразу в переменную окружения (`VITRUM_KS_PASS`); проверяй, что команда не выведет их в лог. Если секрет попал в вывод, скажи автору.
- Секреты и файлы с настоящими данными держи вне проекта (`~/secrets/`, `~/links.txt`). В `.gitignore` уже: `keystore/`, `local.properties`, `libxray.so`, базы geo.
- Перед коммитом: поиск по проекту на токен, пароль, `vless://` с настоящими данными.

## Инварианты (не нарушать без решения автора)
- **Нет открытых портов на 127.0.0.1.** Служебные входы Xray только на unix-сокетах в `filesDir`; TUN-дескриптор передаётся через `XRAY_TUN_FD`.
- Ссылки серверов и конфигурации авто-серверов на диске только в зашифрованном виде (`Vault`, Keystore). Временные конфиги с ключами удаляются после использования.
- `allowBackup=false`, `debuggable` только в debug, http без шифрования запрещён (`network_security.xml`), обновления и подписки только по https.
- Критичная проблема (утечка IP, чужой открытый порт) ограничивает оценку щита; непроверенное очков не даёт.
- Запасной выход авто-серверов не `direct`: при отказе трафик закрывается, а не уходит мимо VPN.
- Внешние ссылки (`vless://`, QR, «Поделиться») добавляются только после подтверждения пользователем; смена адреса подписки (`new-url`) тоже.
- Нет аналитики, рекламы и трекеров. HWID и данные устройства панели не отправляются.

## Чего не делаем
- **Скрытие VPN от других приложений** (банки, госсервисы) разрешено автором (решение от 2026-10-06). Каждую такую функцию делаем только по отдельному заданию автора, до работы предупреждаем о рисках, после работы пишем «не проверено на устройстве». Исключение приложений из VPN (`addDisallowedApplication`) остаётся обычным путём.
- Не копируем код и тексты DUORAY (GPL-3.0): интерфейс и документация написаны заново, общие служебные названия вроде «Через VPN» совпадают. Новые тексты оттуда не берём. Лицензия Vitrum: GNU GPL v3, только версия 3 (файл `LICENSE`).
- Не меняем ключ подписи: с другим ключом обновления не встанут поверх установленных.

## Сборка и проверка
- **APK из Actions сразу уходит в GitHub Release** (pre-release): `build.yml` запускается только по тегу `v*` или вручную (`build` с указанием тега), см. `release` в `build.yml`. Не ждём отдельной просьбы.
- **Всё, что требует root, откладываем** (решение автора): в том числе скрытие VPN от приложений, пока автор не скажет начинать.
- **Сборки и тесты:** на GitHub Actions запуск только по тегу или вручную (`.github/workflows/build.yml`: тесты, отладочный и release-APK), на каждый push тесты не идут, поэтому перед тегом запускай `tools/build.sh tests`. Локально собираем и без тега, если автор попросил. Ключ выпуска в секреты Actions (`VITRUM_KS_BASE64` — jks в base64, `VITRUM_KS_PASS` — пароль хранилища и ключа, алиас `vitrum`) кладёт сам автор (решение от 2026-10-08); агент ключ и пароль не читает и не печатает. Без этих секретов `build.yml` подписывает release одноразовым ключом, с секретами — ключом автора и падает, если отпечаток сертификата не `2c6afebf…a9a1`.
```
tools/SETUP_ENV.sh            # JDK 21 и Android SDK 35 (Linux, WSL)
tools/FETCH_BINARIES.sh --linux   # Xray 26.3.27 с проверкой суммы; --linux для проверок конфигов
tools/build.sh tests          # модульные тесты в фоне; ход: tail -n 3 /tmp/vitrum-build/tests.log
tools/build.sh debug          # или release (нужен keystore/ и VITRUM_KS_PASS), all
```
- Результат тестов смотри по XML-отчётам (`app/build/test-results/testDebugUnitTest/*.xml`), а не по слову «успешно». Часть тестов без внешних файлов выходит вхолостую (см. `docs/HANDOFF.md`).
- Конфиги Xray проверяй настоящим Xray (`xray run -test`), маршруты на живом Xray через unix-сокет.
- Релиз собирается 5–9 минут (R8). Не убивай процессы через `pkill -f gradlew`; при обрыве запусти сборку заново.
- На Windows: WSL или Git Bash; скрипты `tools/*.sh` написаны для bash.

## Выпуск релиза (чек-лист)
1. Версию поднять в `app/build.gradle.kts` (`versionCode`, `versionName`): «Настройки» и «О приложении» берут её из системы (`appVersion`). Версия Xray — `XRAY_VERSION` в `Brand.kt` вместе с `tools/FETCH_BINARIES.sh`.
2. Новая русская строка = запись в `app/src/main/res/raw/i18n_en.tsv`; проверка: `python3 tools/i18n/dict_cov.py`.
3. Все тесты зелёные; релиз и debug-запасной файл собраны.
4. Проверить подпись: `apksigner verify --print-certs`; отпечаток сертификата должен быть `2c6afebf27fbbd2b288f8fb51ca6c9a7c8f4c7ce66793aa67cc04350a6f9a9a1` (он же в `Integrity.kt`); в манифесте нет `debuggable`, `allowBackup=false`; R8 не вырезал JNI-класс `Native`, воркеры и службы.
5. Обновить `CHANGELOG.md`, `docs/HANDOFF.md`, `README.md` (версия), `THIRD-PARTY-NOTICES.txt` (если менялись данные или компоненты), заметки `docs/releases/vX.Y.Z.md` с контрольными суммами.
6. Выложить `Vitrum-X.Y.Z.apk` и `Vitrum-X.Y.Z-debug-fallback.apk` в GitHub Releases; в APK-файлы и в репозиторий не класть ключ и пароль.

## Карта кода (`app/src/main/java/app/rayclient/`)
`Links` разбор ссылок, `ConfigBuilder` конфиг Xray, `RayVpnService` служба (kill switch, автопереключение), `Failover` и `Scenarios` чистая логика, `Shield` оценка защиты, `AppState` и `Subscriptions`/`Profiles`/`Dns`/`Updates` состояние, `Vault` шифрование, `I18n` и `Texts` перевод, `GeoData` и `AsnPrefixes` базы и подсети игр, `SubMeta` метаданные подписки, `AutoSub` и `AutoStore` JSON-режим (авто-серверы), `Integrity` подпись приложения, `*Screen` экраны. Подробнее: `docs/HANDOFF.md`.
