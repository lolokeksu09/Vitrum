# Vitrum: состояние проекта

Автор: Lolokeksu. Правила работы для ИИ-агентов: `AGENTS.md` и `CLAUDE.md` в корне; история версий: `CHANGELOG.md`; заметки выпусков с контрольными суммами: `docs/releases/`. Здесь только текущее состояние.

## Что это
Android-клиент VPN на ядре Xray (Kotlin, Jetpack Compose). Идея и набор функций — по мотивам десктопного клиента DUORAY (Rust, GPL-3.0, github.com/m-a-prod/DUORAY); код и тексты DUORAY не копировались (см. `README.md`, `THIRD-PARTY-NOTICES.txt`). Лицензия Vitrum: GNU GPL v3, только версия 3 (`LICENSE`). Разработка ведётся с помощью ИИ-ассистента, работу на телефоне проверяет автор.
Пакет `app.rayclient`, версия **1.0.0 (versionCode 100)**, minSdk 26, compile/targetSdk 35, только arm64-v8a. Kotlin 2.0.21, AGP 8.7.3, Gradle 8.10.2 (wrapper), Compose BOM 2024.12, JDK 21.
Ядро: Xray-core v26.3.27 (бинарник лежит как `libxray.so`, запускается дочерним процессом через `libspawn.so`: `app/src/main/cpp/spawn.c`, собран NDK 26.3, пересборка нужна только при правке C).

## Среда и сборка (в чистой среде сделать по порядку)
1. `tools/SETUP_ENV.sh`: JDK 21, Android SDK 35 (скрипт проверялся только на уже подготовленной машине).
2. `tools/FETCH_BINARIES.sh [--linux]`: скачивает Xray с проверкой SHA-256 по `.dgst` и по `tools/binaries.sha256`; `--linux` ставит Linux-xray для проверок конфигов (`xray run -test`).
3. `tools/build.sh tests|debug|release|all`: сборка в фоне, логи в `/tmp/vitrum-build/`, флаг `done`.
4. Релиз: нужны `keystore/vitrum-release.jks` (ключ у автора, в репозиторий не входит) и пароль в `VITRUM_KS_PASS`. Отпечаток сертификата выпуска: `2c6afebf27fbbd2b288f8fb51ca6c9a7c8f4c7ce66793aa67cc04350a6f9a9a1` (зашит в `Integrity.kt`; новый ключ = обновления не встанут поверх).
Грабли: не убивай процессы через `pkill -f gradlew` (убьёшь и свою команду); релиз бывает прерывается перезапуском среды, тогда запусти `tools/build.sh release` заново; каждую выдачу проверяй `apksigner verify`, манифест (`debuggable` нет, `allowBackup=false`), ключ.
Выдача: GitHub Actions (`.github/workflows/build.yml`) по тегу `v*` или вручную собирает тесты, отладочный и release-APK и выкладывает пре-релиз `Vitrum-X.Y.Z-release-debugsigned.apk` + `Vitrum-X.Y.Z-debug-fallback.apk` с заметками из `docs/releases/<тег>.md` и SHA-256. Эти файлы подписаны одноразовым ключом сборки; APK с ключом автора собирается локально (`tools/build.sh release`) и выкладывается отдельно. Сессия ИИ-агента не может создавать и удалять релизы и ветки, только запускать Actions.

## Устройство приложения (главное)
- **Нет открытых портов на 127.0.0.1**: служебные входы Xray на unix-сокетах в `filesDir`; TUN-дескриптор `VpnService` передаётся Xray через `XRAY_TUN_FD`. Проверено сканом на телефоне.
- Файлы: `Links.kt` (разбор vless/vmess/trojan/ss/hy2), `ConfigBuilder.kt` (конфиг Xray, маршруты, пресеты игр), `RayVpnService.kt` (служба, kill switch, автопереключение), `Failover.kt` и `Scenarios.kt` (чистая логика, покрыта тестами), `Shield.kt` (оценка защиты: чистая модель `ShieldInput`), `AppState.kt` + `Subscriptions.kt`/`Profiles.kt`/`Dns.kt`/`Updates.kt` (состояние), `Vault.kt` (шифрование ссылок ключом Keystore), `I18n.kt` + `Texts.kt` (перевод на английский), `GeoData.kt`/`AsnPrefixes.kt` (базы и подсети игр), `SubMeta.kt` (метаданные подписки), `Integrity.kt` (подпись приложения), экраны `*Screen.kt`.
- **Перевод**: тексты в коде русские, словарь `app/src/main/res/raw/i18n_en.tsv` (S — фраза или шаблон `{0}`, P — начало фразы). Любая новая русская строка = запись в словарь; проверка охвата: `python3 tools/i18n/dict_cov.py` (хвосты с `{n}` от склейки с переводом строки можно игнорировать). Тест `I18nTest` проверяет согласованность словаря.
- Лицензии: `Licenses.kt`, `res/raw/license_texts.txt` (тексты сверены с оригиналами), экран «Настройки → О приложении», `THIRD-PARTY-NOTICES.txt` в корне.
- **JSON-режим (D-lite)**: `AutoSub.kt` (чистая логика: разбор `<подписка>/json`, подстановка IP, сериализация), `AutoStore.kt` (конфигурации авто-серверов отдельным файлом `autosub.dat`, шифрует Vault), `ConfigBuilder.buildAuto`, `RayVpnService.prepareAuto`, `Subscriptions.fetchAuto/setJson`. Включается по подписке: меню подписки → «Авто-серверы (JSON): включить». Авто-сервер = обычный `Server` с адресом `vitrum-auto://<id подписки>/<название>` (по нему работают избранное и выбор). Из панельного конфига берутся только серверы (outbounds без freedom/blackhole/dns), `routing.balancers`, `burstObservatory`; входы (socks 10808, http 10809), `dns`, правила, direct/block свои. Обычное обновление подписки авто-серверы не стирает.
- **Отступление от «балансировщик как есть»**: у панели `fallbackTag: direct`; пока нет замеров или все узлы недоступны, трафик ушёл бы мимо VPN. Подставляется первый выбранный селектором сервер (`AutoSub.plan`). Проверено живым Xray: с `direct` запрос проходит при полностью мёртвых узлах, с подстановкой получается 503 (закрыто).
- **Белый список для `/json` (аудит 0.25.38)**: `AutoSub.plan` отклоняет конфиг, если в `outbounds`, `balancers`, `burstObservatory` есть ключи, отличающиеся регистром (Xray читает их без учёта регистра, `org.json` нет), или сервер с тегом `direct/block/dns-out/fragment`, или селектор, под который подходит служебный тег. Выход берётся по списку полей (без `sendThrough`, `sockopt.interface/mark`, `tlsSettings.certificates/masterKeyLog`), балансировщик только из `tag/selector/strategy` (известный тип) и нашего `fallbackTag`, замер серверов без `connectivity`, интервал не меньше 30 с (иначе 1 мин), адрес проверки только http(s). Вложенность JSON больше 40 отклоняется до разбора. Ранее сохранённые авто-серверы очищаются при следующем обновлении подписки. Тесты: `AutoSubHostileTest`. Не проверено на устройстве и на живом Xray (поведение Xray по регистру ключей — предположение).
- **Малые правки по аудиту 0.25.38**: `support-url` проходит `httpsUrl` (и при показе кнопки); `fallback-url` берётся только из заголовка ответа и только с публичным именем хоста (`SubMetaParser.publicHost`: не IP, не localhost/.local/.lan/.internal); в Shield пункт IPv6 очков не даёт (INFO, вес 0), kill switch берётся из `killSwitchEffective()`, `alwaysOn/lockdown` сбрасываются при остановке службы; «доверенная сеть» не срабатывает в открытой Wi-Fi (определяется с Android 12, на старых версиях проверить нечем); чтение настроек в `AppState.init` не падает на значении другого типа (`safeInt` и др.). Тесты: `AuditFixesTest`. Не проверено на устройстве.
- **Корректность по аудиту 0.25.38**: при обновлении подписки сервер с той же ссылкой сохраняет id (замеры и выбор не теряются, `fetchSub`); фильтр страны действует, только пока такая страна есть и чипы показаны; при «Остального трафика: блокировать» DNS (порт 53) идёт через VPN, иначе домены из правил «Через VPN» не разбирались (`ConfigBuilder`); правила IP, порты и домены проверяются до сохранения (`RuleCheck`, при неверной записи правило не сохраняется); отчёт о проблеме собирается в фоне с задержкой, журнал читается с конца (`LogTail`, он же в `RayVpnService`); base64 подписки с переводами строк и маршрутизация `happ` с «+» декодируются. Тесты: `RuleCheckTest`. Замена id серверов (`fetchSub`) и фильтр страны юнит-тестами не покрыты (зависят от `AppState` и экрана). Не проверено на устройстве.
- **Остальные правки по аудиту 0.25.38**: `RayVpnService` (перезапуск Xray из `watch` и `failover` только через `relaunch(g)` под замком `pidLock`, исключение в `watch` превращается в ошибку подключения, `gameMon` не выходит при перезапуске Xray, режим «Только выбранные» без ни одного приложения не стартует); общий срок 60 с на чтение ответа подписки, JSON и whitelist; `save()` итерирует снимки списков; `fetchSub` не затирает правки подписки за время загрузки; `new-domain` сохраняет порт; `LeakCheck.parseIp` и `AsnPrefixes` принимают только настоящие адреса; `isLocalAddr` знает IPv4 внутри IPv6; `HeadProbe.get` читает не больше 400 символов; в отчёте о проблеме хосты `android.*`, `*.so` не пропускаются, `::ffff:` маскируется; в диалоге обновления показан хост страницы загрузки; «Трафик по приложениям» не показывает результат другого периода; тексты про kill switch и мастер подключения уточнены. Не сделано: `PR_SET_PDEATHSIG` в `spawn.c` (сигнал привязан к потоку, создавшему процесс; рабочий поток подключения завершается, и Xray был бы убит), подпись/хэш geoip отдельно от источника, перенос копирования баз из `init`. Тесты: `AuditFixes2Test`. Не проверено на устройстве.
- В авто-режиме в конец правил добавлено `tcp,udp → balancerTag`: без него трафик вне правил шёл бы в первый выход списка, а не в балансировщик (тест `routesGoThroughBalancerNotThroughFirstOutbound`).
- Свой автопереключатель (`failover`) для авто-серверов выключен (выбирает балансировщик), а авто-серверы исключены из кандидатов; замеры пинга и игровой тест их пропускают.
- Тесты: модульные (см. отчёты `app/build/test-results/testDebugUnitTest/*.xml`, на 1.0.0 — 257 тестов, 0 падений, 5 пропусков). Часть читает файлы вне проекта через `System.getProperty("user.home")` и без них пропускается или проходит вхолостую: `~/links.txt` (ссылки подписки), `~/dl/xl/xray` (Linux-xray, ставит `FETCH_BINARIES.sh --linux`), `~/secrets/sub.json` (ответ `/json`; `RealJsonSubTest` пишет конфигурации в `/tmp/vitrum-test/json`). Секреты держать только вне проекта.

## Проверено живьём, не на телефоне (всё остальное на устройстве не проверялось)
Конфиги проходят `xray run -test`; правила маршрута для подсетей Riot/Valve/Blizzard и российских IP проверены на настоящем Xray через unix-сокет; загрузка и проверка суммы `geoip.dat` runetfreedom; панель автора (Remnawave): заголовки (`profile-update-interval: 1`, `subscription-refill-date`, `announce`, `support-url`, `profile-web-page-url`; `new-url`/`new-domain`/`fallback-url` нет).
**Проверено живым Xray 26.3.27 (не на телефоне), JSON-режим:** все 12 конфигов с балансировщиком × 2 варианта настроек проходят `xray run -test`; маршрут через unix-сокет `probe-in` ведёт в балансировщик; на панели автора при первой проверке 10 из 12, при второй (в другое время) 9 из 12 авто-серверов реально отдают трафик через узлы (балансировщик переключает узлы), остальные (в разных проверках «Wi-Fi • Авто-выбор», «LTE x1», «Standard») ни одного узла из среды проверки не открыли (Reality/TLS из неё недоступны), по ним проверено только «закрыто, а не мимо VPN». Поведение с настоящим TUN не проверялось (в среде нет TUN: тест шёл без `tun-in`).
**Не проверено на устройстве:** авто-серверы и их экраны, нагрузка и расход батареи от `burstObservatory` (замеры каждые 30 с–2 мин по 16–40 узлам; значения панели не менялись), новые экраны, скачивание баз, диалог переезда, Keystore на реальной прошивке, определение «Постоянного VPN», R8-сборка при запуске, поведение в фоне на ColorOS.

## Что осталось
1. **Проверка на устройстве** всего, что отмечено выше как не проверенное. Подтверждение даёт автор.
2. **Выпуск с подписью автора.** Релизы в GitHub сейчас подписаны одноразовым ключом Actions и не встают поверх выпуска с ключом автора. Варианты: собрать локально `tools/build.sh release` и выложить файл; или по решению автора положить ключ в секреты Actions (без такого решения ключ в Actions не передаётся).
3. **Из аудита сознательно не сделано:** `PR_SET_PDEATHSIG` в `spawn.c` (сигнал привязан к потоку, создавшему процесс; рабочий поток подключения завершается, и Xray был бы убит; сейчас осиротевший Xray убирает `XrayOrphans`), перенос копирования баз из `init` в фон (риск гонки с читателями баз выше пользы), подпись geoip отдельно от источника (вместо неё `GeoSanity`), проверка запуска служб переднего плана из Worker на Android 12+.
4. **Щит:** пакеты B, C, D сделаны (см. `CHANGELOG.md`, 0.25.3–0.25.7).
5. Доступность: роль «кнопка» у плашек и строк списка; английский текст может не помещаться в кнопки.
6. Решения автора: копия белого списка hxehex внутри APK (лицензия репозитория не указана): оставить или скачивать только при включении; нужна ли Ed25519-подпись `update.json` (на Android мало смысла: ОС не даст поставить обновление с другим ключом).
7. Скрытие признаков VPN от приложений разрешено автором (2026-10-06), но требует root и **отложено** вместе со всеми root-функциями; сейчас рабочий путь только исключение приложений из VPN (`BankApps.kt`, список ручной, может устареть).
