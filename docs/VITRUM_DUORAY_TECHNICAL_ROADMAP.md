# Vitrum — техническая дорожная карта после сравнения с DUORAY-Mobile

**Статус:** первый изолированный runtime-прототип реализуется в PR #80; Debug CI прошёл, расширенная Clone CI-компиляция добавлена и ожидает подтверждения; выполнение на ARM64-устройстве ещё не подтверждено.  
**Дата аудита:** 2026-11-07.  
**Область:** VPN-ядро, JSON-подписки и выбор серверов по типу сети.  
**Важно:** этот документ описывает направление и критерии будущих патчей. Он не утверждает, что перечисленные функции уже реализованы, и не разрешает менять сетевое поведение без отдельного этапа реализации и проверки.

## Текущий статус реализации — 2026-11-07

- PR #80: [feat: probe Xray runtime launch paths on ARM64](https://github.com/lolokeksu09/Vitrum/pull/80), draft.
- Добавлен `XrayRuntimeProbeTest` в `app/src/androidTest`: отдельно проверяет запуск встроенного Xray из `nativeLibraryDir` и запуск staged-копии через `/system/bin/linker64`.
- Добавлены AndroidX instrumentation dependencies и runner. Проверки охватывают оба варианта приложения: `assembleDebugAndroidTest` и `assembleCloneAndroidTest`; сам Clone APK собирается через `assembleClone`.
- `clone` — build type, который использует общий `app/src/main` и отдельные ресурсы/идентичность пакета из `app/src/clone`. Следовательно, общие изменения приложения входят в Clone при его пересборке; отдельного переноса каждого Kotlin-файла не требуется.
- `tools/build.sh`, PR checks, официальный release workflow и Clone pre-release workflow расширены для сборки Clone runtime probe. Workflow [`xray-runtime-probe.yml`](../.github/workflows/xray-runtime-probe.yml) сохраняет Clone APK и instrumentation APK для Debug/Clone; он не подписывает авторским ключом и не публикует официальный релиз.
- Предыдущий CI run [#42385838450](https://github.com/lolokeksu09/Vitrum/actions/runs/42385838450) прошёл `testDebugUnitTest` и компиляцию Debug instrumentation APK. После добавления Clone targets требуется отдельный успешный CI run именно для новой ревизии.
- **Пока не проверено:** фактический запуск обоих путей Xray на физическом ARM64; сборка/компиляция на CI сама по себе этого не доказывает. До результата не выбирать linker как runtime, не реализовывать менеджер загрузки и не менять путь запуска в `RayVpnService`.
- Не менялись VPN/TUN/JNI runtime, Kill Switch, Vault, данные пользователя, package ID официальной сборки, versionCode/versionName и ключ подписи. Это тестовый каркас, а не готовый Xray Core Manager.

## 1. Цель

Развивать Vitrum как самостоятельный Android VPN-клиент, используя DUORAY-Mobile как технический ориентир. Улучшить управление версиями Xray, совместимость со сложными JSON-подписками и автоматический выбор серверов по сети, **не переписывая приложение на Rust/Slint и не заменяя существующую архитектуру**.

Основной принцип: заимствовать проверяемые технические идеи и совместимые сценарии, но не переносить вслепую реализацию другого приложения. Сначала фиксируются контракты и ограничения Vitrum, затем выполняются изолированные изменения с регрессионными тестами.
