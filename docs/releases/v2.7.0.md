# VITRUM 2.7.0 — Encrypted DNS 853 Guard & Private DNS (pre-release)

Android 8+, ARM64, application ID `app.rayclient`; versionCode 270 / versionName 2.7.0. Installs over the official VITRUM 2.6.0 with the original author signing certificate.

## Changes
- **Encrypted DNS route guard:** for apps included in Android VPN, connections targeting **TCP port 853** (usually DNS-over-TLS/DoT) and **UDP port 853** (usually DNS-over-QUIC/DoQ) route through Xray proxy/balancer before the broad `defaultAction=direct`, LAN and regional direct rules. This routing does not decrypt or hijack encrypted traffic.
- **Explicit exclusions preserved:** user rules take precedence; `blockV6`, TCP-only and UDP-only transport restrictions remain higher priority, and apps excluded from the VPN are untouched.
- **Privacy Shield:** on one manual action, displays configuration-only DNS 53 and 853 route predictions for selected DNS IPs, and the Android Private DNS mode observed on the active network of the VITRUM process (strict, opportunistically upgraded, inactive, unavailable, or unsupported on Android 8).
- **No storage of Private DNS hostname, IP or traffic**, no background probes or external DNS queries for this feature. Adds Android's normal `ACCESS_NETWORK_STATE` permission solely for this public system status.
- New JVM regression tests on port 853 first-match routing, explicit direct/block exceptions, IPv6 and transport restrictions, and Private DNS mode classification; Android 16 UI smoke and Xray JSON schema checks required for release.

## Important behavior change and limitations
- Connections to 853 that previously used a default direct route now use the VPN server. Local/private DoT/DoQ servers may become unreachable without an explicit direct rule. DoQ requires a working UDP path through the selected VPN server. This may affect affected DNS clients.
- Android Private DNS may target a **different server than the DNS IP list** used for route predictions. The network reported to the VPN process may be the underlying default network, rather than the tunneled application's route.
- Encrypted DNS over HTTPS on port 443, DNS on custom ports, excluded apps, DNS over non-standard transports, and live Android TUN packet routing remain unmeasured.
- Local rule prediction, HTTP through the Xray service socket, and Private DNS system mode **do not prove DNS/IPv4/IPv6 leak-freedom**. The Shield's leak state remains `UNKNOWN`.
- Physical ARM64 verification (Wi-Fi ↔ mobile, Always-on, Lockdown, split tunneling, DNS leak observer) is outstanding; this is a pre-release.
