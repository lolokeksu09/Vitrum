# Vitrum 2.1.0 — Toolchain and reliability maintenance

**Release channel:** pre-release candidate until maintainer device acceptance.  
**Application:** `app.rayclient` · Android 8.0+ · ARM64 · `versionCode 285` · `versionName 2.1.0`.  
**Updates:** the official APK must be signed with the existing Vitrum maintainer certificate. The separately signed debug fallback cannot update the official app.

Vitrum 2.1.0 is a maintenance release based on the current `main`. It contains the VPN and application features already present in 2.0.0. This release is primarily a dependency and build-system upgrade, not a new VPN protocol or routing feature release.

## Changed

- Upgraded Kotlin Android and Compose compiler plugins together to 2.4.21; migrated the JVM 17 target configuration to the supported compiler options DSL.
- Upgraded Android coroutines from 1.9.0 to 1.11.0.
- Upgraded Jetpack Compose BOM from 2024.12.01 to 2026.09.00 and updated the Material3 Text localization wrapper to use named arguments compatible with the newer API.
- Upgraded Android Gradle Plugin from 8.7.3 to 9.5.1 and Gradle from 8.10.2 to 9.6.0. Compile SDK is Android 37.0 with matching Build Tools. Existing minSdk and targetSdk levels are unchanged.
- Temporarily retained the existing Kotlin plugin integration under AGP 9 through the documented compatibility flags. Full built-in Kotlin migration is not part of this release.
- Updated GitHub Actions dependencies and added CI safeguards for Kotlin plugin alignment, full JVM tests, Clone APK identity, and release artifact transfer.

## Validation and restrictions

- Pull-request CI verifies dependency resolution, unit tests, Debug and isolated Clone compilation, release R8 compilation without the maintainer key, and the applicable Lite workflows.
- A successful build **does not** establish correct VPN/TUN/DNS/IPv6 behavior, leak prevention, reliable failover or battery behavior on a physical device.
- Verify the exact APK SHA-256 and package/certificate metadata after the signed release workflow finishes.
- Before stable promotion, test on a physical Android ARM64 device: connect/disconnect, A→B server switching and rollback, stop/start races, Wi-Fi↔mobile, sleep/recovery, DNS/IPv4/IPv6 and Android always-on/lockdown.
- If the author signing secrets are missing, the release workflow must fail rather than publish an unsigned or differently signed official APK.
