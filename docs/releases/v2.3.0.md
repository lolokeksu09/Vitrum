# Vitrum v2.3.0 — Automatic Failover Recovery (Pre-release)

Package `app.rayclient`, versionCode 230, versionName 2.3.0. Android 8.0+, ARM64. Updates official v2.2.0 using the existing maintainer key.

If an Xray candidate fails to start, VITRUM tries the next candidates. If none responds through the service Unix socket, it attempts a verified rollback to the previous server. If rollback also fails, TUN remains blocked even when the app kill switch is disabled. Server selection changes only after an HTTP response and process verification; STOP or a new connection cancels stale results.

The event journal now includes a separate automatic-rollback event. Reports still contain only event types, timestamps, and counters—no server addresses or keys.

**Not device-tested.** JVM tests and CI builds do not prove real ARM64 VPN traffic, DNS/IPv4/IPv6 leak safety, Wi-Fi↔LTE transitions, Always-on/lockdown, or actual fail-closed behavior. An HTTP response does not prove the absence of leaks. See `docs/ANDROID_RUNTIME_CHECKS.md`, v2.3.0 section, for maintainer checks.

Requires the existing maintainer certificate, SHA-256 `8cb8b675f97239948f0b93ac4208464e856397d6141268798129c00337205c61`. A mismatch or missing secrets blocks publication. GitHub Actions adds artifact checksums during release.
