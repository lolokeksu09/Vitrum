# Vitrum 2.1.1 — WorkManager startup hotfix

**Channel:** pre-release pending physical ARM64 device acceptance.  
**Application:** `app.rayclient` · Android 8.0+ · ARM64 · `versionCode 286` · `versionName 2.1.1`.  
**Update:** the official APK is built with the existing Vitrum maintainer certificate and is intended to install in place over the author-signed 2.1.0 / 2.0.0. Do not uninstall or clear app storage to perform the update.

## Fixed

- **Startup crash in the 2.1.0 pre-release:** AndroidX WorkManager failed before `MainActivity` because R8 stripped the zero-argument constructor of the generated `androidx.work.impl.WorkDatabase_Impl` class. On affected devices, Android displayed an "App keeps stopping" dialog.
- Added a narrowly scoped R8 keep rule for that constructor. Optimized minified release builds remain enabled.
- Added an automated DEX-level regression check for the constructor, required by both pull-request CI and the official signed APK publishing workflow.
- Added Android 13 emulator smoke tests for debug and R8 release startup to catch UI startup regressions earlier.

## Evidence and verification

- A maintainer-provided Android crash log shows `java.lang.NoSuchMethodException: androidx.work.impl.WorkDatabase_Impl.<init> []` on repeated starts of 2.1.0.
- The published 2.1.0 release APK's DEX contains `WorkDatabase_Impl` **without** its required constructor. The new DEX regression guard correctly fails on that published APK.
- The corrected optimized candidate preserves the constructor, as checked in GitHub Actions. The final release workflow must also pass this check and validate the existing maintainer signing certificate before publication.
- Build and emulator verification do not establish that VPN/TUN, server switching, or DNS leak protections work correctly on all real devices.

## Installation and acceptance

1. Install the **author-signed** `Vitrum-2.1.1.apk` from this GitHub Release over the existing Vitrum app. The debug/Clone APK is not an update for the official package.
2. Launch and relaunch Vitrum without clearing storage. Verify that existing servers, profiles, and subscriptions remain available.
3. Check VPN connect/stop, server switch and rollback, Wi-Fi/mobile transitions, and relevant DNS/IPv4/IPv6 behavior on a real ARM64 device.
4. Promote to **Stable** only after maintainer device acceptance; no automatic stable promotion is allowed.

**No VPN, TUN, DNS routing, subscription or app-data migration logic changes are intended in this hotfix.** The distinct Vitrum Lite release remains `lite-v1.0.0`.
