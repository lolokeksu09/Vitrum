# Vitrum 2.0.0

**Consolidated primary release** · Android 8.0+ · ARM64 · package `app.rayclient` · Android versionCode 284.

Vitrum 2.0.0 consolidates the app's primary feature set and improvements accumulated after the first release: UI, server management, VPN lifecycle, routing, DNS, privacy diagnostics, game scenarios, localization, and data-storage reliability.

## Added
- **Onboarding 2.0:** three first-run steps, pinned actions, independently scrollable content, system Back navigation, and small-screen adaptation.
- **Settings search:** searches section names and descriptions while preserving diagnostic-result availability across tab changes.
- **VPN Event History:** separate Journal event tab for VPN start/stop, Xray start, manual/automatic server switch, rollback, TUN blocking, recovery, and network-availability changes. Stores the latest 40 events and coalesces repeated events.
- **Diagnostic reports:** copyable event report with timestamps and privacy warning. Server keys, subscription URLs, IPs, domains, and raw Xray logs are excluded.
- **Privacy Shield diagnostics:** manual common TCP-port checks and IPv4/IPv6 HTTP checks through a private Xray Unix socket; direct-IP comparison requires separate user consent.
- **DNS Route Audit:** manual analysis of expected UDP/53 and TCP/53 routes, accounting for Xray rule order, user IP/CIDR and port rules, DNS interception, GeoIP uncertainty, and direct routes.
- **Encrypted DNS audit:** expected DoT TCP/853 and DoQ UDP/853 route analysis for configured DNS IPs; manual Android Private DNS mode observation through `LinkProperties`.
- **Strict DNS validation:** only valid numeric IPv4/IPv6 addresses enter Xray config; duplicate entries are removed, and a fallback list with a warning is used when no valid values remain.
- **Advanced routing explanations:** expected route for an app, domain, IP, port, or protocol; display of Other Traffic mode and warnings about direct VPN bypass.
- **Game scenarios:** game mode with server selection, latency testing, and game-app VPN exclusions.
- **Localization:** Russian and English UI across Home, Servers, Routing, Settings, Journal, Privacy Shield, Game, Backup, and dialogs.

## Improved
- **Home:** prioritizes actual VPN state, the primary connect action, and selected server; diagnostics and statistics remain secondary.
- **Visual system:** true AMOLED `#000000` background, restrained surfaces, Manrope, VITRUM violet accent, and standard Material 3 bottom navigation instead of glass gradients and continuous decorative animation.
- **Servers:** filtering, country selection, sorting, favorites, latency, clear selected-server state, and usable actions for long names.
- **Game server selection:** uses the shared server-list mechanism; current selection remains explicit during active VPN or blocked TUN states.
- **Server switching:** the new server is selected only after a response through the Xray service socket; on failure, the previous server is restored where possible.
- **Automatic selection:** failure to start one candidate does not stop iteration; after candidate failures, recovery of the previous server is checked.
- **VPN state preservation:** server and subscription operations must not silently reset the active route while VPN is connected or transitioning.
- **DNS routes:** normal DNS TCP/UDP 53 is routed through Xray before generic `direct`/geo rules when Xray DNS interception is not enabled. For TCP/UDP 853, explicit user rules retain priority, followed by a separate Xray routing rule.
- **Custom DNS:** invalid values are excluded from config; fallback DNS is applied with an explicit warning.
- **Diagnostics:** results are bound to the current VPN session, server, and network state; stale port/IP results are not presented as current. Result freshness is checked separately.
- **Accessibility:** primary actions have touch targets of at least 48 dp; lists/settings account for font scaling, long labels, and TalkBack.
- **Journal:** filters have clear empty states and reset; VPN events are separate from detailed visited-address logging.
- **Subscriptions and auto-servers:** encrypted state is persisted atomically; backup reads are size-limited.
- **Updates:** version, tag, and release certificate are checked.
- **Runtime assets:** Xray fallback download uses official GitHub Releases metadata and retains checksum verification.

## Fixed
- STOP/START races and stale watcher, failover, and network-recovery results.
- Premature display of a new server as active before connection verification.
- Server iteration after a candidate Xray startup failure and rollback handling.
- On rollback failure, TUN remains blocked, including when the app kill switch is disabled; an explicit VPN disconnect still closes TUN.
- Android foreground VPN service startup rejection: Xray does not start without system permission and the user sees an error.
- Server/subscription operations during active or transitioning VPN states.
- Invalid IPv4/IPv6 DNS addresses, duplicate values, and fallback when no valid address remains.
- Pinger shutdown: JNI stop is not called for a process that was never started.
- GeoData replacement only occurs after the downloaded file passes SHA-256 verification.
- Connection cancellation states, rapid auto-selection button locking, Journal filtering, and empty server results.
- Local IPv6 CIDR parsing and route-preview explanations for catch-all and early transport restrictions.
- Demo data isolation from the user profile.

## Reworked
- Home, bottom navigation, server lists, and settings use a consistent minimal AMOLED/Material 3 system.
- Status messaging distinguishes configuration analysis from observed diagnostic evidence.
- Subscription, profile, and data-persistence workflows are more predictable.

## Verification boundaries

A passing build or HTTP response through the Xray service socket does not prove leak-free routing for all Android apps. DNS leak status remains UNKNOWN without an independent observer. Physical ARM64 VPN/TUN, DNS/IPv4/IPv6, network-transition, Always-on/lockdown, and kill-switch behavior require device testing. The maintainer reported successful installation and in-place update on their device; this is user-reported device verification, not a CI result.
