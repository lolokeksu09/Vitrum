# VITRUM v2.5.0 — DNS Route Guard & IPv6 Evidence (Pre-release)

**Package:** `app.rayclient` · **versionCode:** 250 · **versionName:** 2.5.0 · **Android:** 8+ · **ABI:** ARM64. Updates official 2.4.0 when the maintainer certificate matches.

## Changes
- **DNS Route Guard:** in normal mode, Xray routes DNS over TCP/UDP port 53 through the proxy or primary balancer, even when `defaultAction=direct`, "Everything except Russia", or LAN bypass could otherwise send it directly.
- **User rule priority:** explicit user rules for port 53 retain priority. When DoH, FakeDNS, or `blockV6` is enabled, the existing `dns-out` interception remains in effect.
- **IPv6:** Android `::/0` route and `blockV6` rules are unchanged. Shield separately explains that an HTTP check through the Xray socket does not prove IPv6 protection for other Android apps.
- **DNS diagnostics:** configuration policy is shown separately from **DNS leak status: UNKNOWN** until an independent test exists. Unsupported claims of guaranteed IPv6 leak prevention were removed.
- JVM rule/configuration tests; real `xray run -test` for three representative configs; Android 16 UI smoke; release APK built only with the current maintainer key and certificate SHA-256 verification.

## Behavior change and limitations

**DNS through a local LAN resolver** (for example, 192.168.x.x) may stop working while the VPN is active if that resolver cannot be reached from the VPN server. In that case, add an **explicit direct rule** for the required DNS traffic or choose a public resolver. Apps excluded from the VPN still have a direct network path; VITRUM does not control their DNS.

DoH/DoT on ports 443/853 and Android Private DNS may require separate routing. A configuration check for DNS port 53 **does not prove that DNS leaks are impossible**. An IPv6 timeout does not prove leak-free blocking. CI/emulator tests do not replace physical Android ARM64 testing with Wi-Fi↔LTE, system Always-on, and lockdown.

Until physical-device verification, this is a **pre-release**.
